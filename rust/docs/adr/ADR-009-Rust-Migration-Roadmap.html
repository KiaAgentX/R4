وضعیت: Proposed — در انتظار تأیید مالک دامنه: بک‌اند نسل ۳ (Agent-One v4.4.3) Rust · edition 2024 · stable فرانت: React/Aurora — دست‌نخورده تاریخ سند: ۲۰۲۶-۱۱-۱۱ جایگزین: هیچ (اولین سند مهاجرت زبان)

۱) خلاصه مدیریتی

امپراتوری DropAgentX در سه نسل تکامل خورده و نسل سوم (Agent-One) هسته‌ای ساخته که فلسفه‌اش از روز اول Rust بوده: پول عدد صحیح برندشده، الگوی Result دست‌ساز با ممنوعیت عبور exception از مرز دامنه، و هسته‌ای با صفر وابستگی ران‌تایم. این سند مسیر برداشتن «لباس TypeScript» از این معماری و پوشاندن آن با زبانی می‌دهد که آن مفاهیم را به‌جای شبیه‌سازی، به‌صورت بومی و کامپایلری تضمین می‌کند.

💡 چرا الان بهترین پنجره است؟

فاز ۷ نقشه راه فعلی (پورت قابلیت‌های نسل ۱: USDT، گیمیفیکیشن، حافظه) هنوز شروع نشده. هر قابلیتی که اول به Node دوخته شود، بعداً باید دوباره به Rust پورت شود — یعنی هر هفته تأخیر در تصمیم، هزینه مهاجرت را بیشتر می‌کند. این سند را باید قبل از فاز ۷ تصویب کرد.

محور تصمیمجمع‌بندی
استراتژیبازنویسی کامل بک‌اند به Rust (به انتخاب مالک) — نه Rust-core هیبرید، نه وضعیت quo. فرانت و قراردادهای HTTP دست‌نخورده می‌مانند.
دامنه پورت۷ پکیج TS بک‌اند به حجم ۱۰,۷۱۷ خط: domain · server · bot · ai-gateway · llm · contracts · nation. داشبورد (۶,۵۱۳) و Mini App (۳,۰۰۹) در React می‌مانند.
تلاش~۷۴۶ ساعت خالص (۱۹ نفر-هفته) → ۲۰ هفته تقویمی با فازبندی زیر؛ مدل محاسبه: نرخ بهره‌وری ۲۸ خط/ساعت برای «پورت با اسپکِ تست‌محور» + سربار ۱٫۲۵ + ضریب یادگیری ۱٫۳.
ریسک اصلیاختلاف رفتار در گذار (parity drift) و ناهماهنگی قابلیت‌های teloxide با grammY — هر دو با پلن dual-run و گلوگاه parity مهار می‌شوند.
بازده استراتژیکتک‌باینری مستقل (~۲۰MB)، حافظه مقصد ~۲۰–۳۰MB (تخمینی، در برابر ~۱۲۰–۱۵۰MB اکوسیستم Node)، استارت سرد زیر ۱۰۰ms (تخمینی)، حذف کامل کلاس‌های باگ null/data-race، و — مهم‌تر — ادعای فروش قابل‌دفاع «هسته مالی memory-safe و قابل‌آدیت» برای مشتریان سازمانی وایت‌لیبل.
چیزی که بدتر می‌شودسرعت iterate روی فیچرهای AI/JSON، pool استخدامی کوچک‌تر، و زمان کامپایل طولانی‌تر. این‌ها در معیارهای تصمیم صادقانه شمرده شده‌اند.

✅ نتیجه

این کدبیس «شبیه‌سازی Rust در TypeScript» است — یعنی مهاجرت، ترجمه‌ی مفاهیمی است که از قبل با ذهنیت Rust طراحی شده‌اند. گران‌ترین بخش مهاجرت‌های معمول (بازطراحی معماری) اینجا از قبل انجام شده؛ همین موضوع نرخ بهره‌وری ۲۸ خط/ساعت (به‌جای نرخ greenfield) را قابل‌دفاع می‌کند.

۳) اهداف و غیر-اهداف

🎯 اهداف (Goals)

  • G1 — صحت کامپایلری پول: ناممکن‌شدن کلاس‌های باگ overdraft/float/unbalanced در سطح type-system؛ حذف چک‌های ران‌تایم برند.
  • G2 — تک‌باینری عملیاتی: یک پروسه = سرور + بات + sweep، بدون Node runtime؛ Dockerfile دو مرحله‌ای، ایمیج کوچک‌تر، استارت سرد سریع.
  • G3 — حفظ قراردادها: همان مسیرهای /api/v1/*، همان OpenAPI 3.1، همان دیتابیس — داشبورد و Mini App بدون حتی یک خط تغییر کار کنند.
  • G4 — پورت کامل تست: ۱۸۷ تست بک‌اند + ~۶۰ parity/property/fuzz جدید = هدف ~۲۴۷ تست Rust (مجموع با فرانت: ~۳۶۰).
  • G5 — گذار بدون توقف: dual-run با feature-flag درصدی؛ zero downtime؛ rollback یک‌متغیره.
  • G6 — آمادگی فاز ۷: بعد از cut-over، قابلیت‌های نسل ۱ (USDT ramp، گیمیفیکیشن، حافظه/RL) مستقیماً روی هسته Rust ساخته شوند.

🚫 غیر-اهداف (Non-Goals)

  • بازنویسی فرانت React/Aurora یا Mini App (فقط اتصال WASM اختیاری).
  • مهاجرت SQLite→PostgreSQL در همین سیکل (sqlx هر دو را پوشش می‌دهد؛ PG سیکل بعدی).
  • افزودن قابلیت جدید در حین مهاجرت — feature freeze روی بک‌اند تا پایان فاز ۸.
  • پورت نسل ۱ (HermesA پایتون) و بایگانی‌ها؛ آن معماری مستقل می‌ماند.
  • microservices — همان تک‌پروسه‌ای بودن فعلی حفظ می‌شود.

۴) معماری قبل/بعد

شکل ۱ — نیمه چپ: وضعیت فعلی TS. نیمه راست: هدف Rust. سبز: هسته دامنه با تضمین کامپایلری. آبی: لایه‌های عملیاتی. فرانت هر دو سمت یکسان است.

⚠️ صادقانه بگوییم

اگر معیارِ «سریع‌ترین رسیدن به فاز ۷» تنها معیار بود، TS می‌ماند. این سند روی انتخاب آگاهانه‌ی مالک (بازنویسی کامل) بنا شده؛ پس تمرکز ما کمینه‌کردن هزینه‌ی مسیر انتخاب‌شده است — نه اقناع دوباره.

📌 قانون طلایی مهاجرت

قرارداد ثابت، پیاده‌سازی متغیر. هیچ مسیر HTTP، هیچ شکل JSON و هیچ ستون دیتابیسی تغییر نمی‌کند. مهاجرت فقط «موتور زیر در» را عوض می‌کند — همین است که parity testing را ممکن می‌کند و rollback را یک‌متغیره.

۷) فازهای مهاجرت (۰ تا ۸) — هر فاز با گیت سبز

مثل ROADMAP.md نسل سوم: هر فاز خروجی مستقل دارد، فاز بعدی فقط وقتی شروع می‌شود که فاز قبل سبز باشد. جمع فازها: ۷۲۵ ساعت + ۲۱ ساعت بافر = ~۷۴۶ ساعت.

Phase 0زیرساخت و قواعد بازی ۱ هفته · ۲۰hبدون رفتار جدید

دامنه کار

  • ساخت rust/ workspace در مونوریپو: crates/domain · contracts · server · bot · ai · tooling + members و workspace.dependencies قفل‌شده.
  • CI جدید: cargo fmt --check → clippy -D warnings → cargo test → cargo build --release؛ cargo-deny برای مجوز/آدیت وابستگی‌ها؛ کش sccache.
  • قواعد سراسری: #![forbid(unsafe_code)]، ممنوعیت unwrap/expect خارج از تست (clippy lint سفارشی)، error model یکدست.
  • تصمیم ثبت‌شده: نسخه‌های پایه (axum/teloxide/sqlx/utoipa) + خط‌مشی به‌روزرسانی.
✅ معیار پذیرش (هدف)
  • CI سبز روی workspace خالی با hello-handler؛ قواعد فورس‌شده؛ cargo deny check پاس.
  • سند ADR-009 merge شده و این سند به docs/adr/ اضافه شود.
Phase 1هسته دامنه خالص — dropagentx-domain قلب مهاجرت۳ هفته · ۱۴۰h

دامنه کار

  • money.rs: Din(u64) + TryFrom<i64> + mul_bps با floor و گارد سرریز (پورت ADR-002).
  • ledger.rs: دفتر دوطرفه تغییرناپذیر، ≥۲ پستینگ و Σ=0 (پورت ADR-003)، قوانین جهت حساب (user/escrow/treasury هرگز منفی؛ mint هرگز مثبت؛ burn هرگز منفی)، idempotency_key با بازپخش امن.
  • escrow.rs: ماشین حالت ۸ وضعیته (پورت ADR-004) با enum EscrowStatus و match جامع + TTL sweep خالص.
  • charter.rs: منشور ۱۰ ماده‌ای به‌صورت policy قابل‌تست (مالیات ۱۰٪ با floor، سقف ضرب سالانه، آستانه HITL ۵۰٬۰۰۰ Đ) — ادغام packages/nation.
  • events.rs: رویدادهای دامنه با id قطعی.
  • تست‌ها: پورت ۴۰ تست فعلی + property-based جدید (proptest): ۳۰۰ عملیات تصادفی seed-دار → Σ همیشه صفر؛ replay با idempotency؛ مسیرهای غیرمجاز اسکرو رد؛ مالیات دقیقاً ۱۰٪.
✅ معیار پذیرش (هدف)
  • ۴۰/۴۰ تست پورت‌شده سبز + ≥۱۲ property سبز؛ cargo test -p dropagentx-domain تمیز.
  • صفر وابستگی extern در crate؛ #![no_std]-compatible logic (بدون I/O)؛ Miri بدون خطا روی test suite.
  • مقایسه رفتاری: هر fixture موجود TS، خروجی یکسان در Rust (golden files).
Phase 2پیوندersistence — sqlx + Outbox + Genesis ۲ هفته · ۸۰h

دامنه کار

  • آداپتر persistence: load دفتر کامل در تراکنش تعاملی → اجرای دامنه خالص → persist (الگوی فعلی حفظ می‌شود) با sqlx::Transaction.
  • Outbox برای DomainEventها + جدول audit؛ idempotency با unique constraint (مسابقه‌ی retry دوبار پول جابه‌جا نمی‌کند).
  • پورت migrate-legacy.ts → migrate-legacy.rs: ۴۶۶ کاربر → user:tg:<id>، genesis یک‌بارمصرف با idempotency قطعی legacy:genesis:v1، جدول گرد‌کردن صریح ADR-002.
  • پورت genesis-proof.rs: ممیزی خارجی با SQL خام (بدون ORM) — Σ کیف‌ها = 187,672 Đ · Σ پستینگ‌ها = 0.
✅ معیار پذیرش (هدف)
  • اجرای مهاجرت روی snapshot واقعی دیتابیس فعلی → همان عدد 187,672 Đ و trialBalance.balanced == true؛ اجرای دوباره → صفر تغییر (replay امن).

/// ADR-002 — Money is an integer. Always. Never a float.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub struct Din(u64);   // فیلد خصوصی — ساخت خارج از مرز غیرممکن است

impl TryFrom<i64> for Din {
    type Error = DomainError;
    fn try_from(n: i64) -> Result<Self, Self::Error> {
        if n < 0 { return Err(DomainError::NegativeAmount(n)); }
        Ok(Din(n as u64))        // بعد از این مرز، Din منفی «نوعی ناموجون» است
    }
}

/// مالیات ۱۰٪ با floor — منشور ماده ۴؛ کامپایلر سرریز را نشان می‌دهد
pub fn split_seller_tax(gross: Din, bps: u32) -> Result<(Din, Din), DomainError> {
    let raw = (gross.0 as u128) * (bps as u128) / 10_000;
    let tax = u64::try_from(raw).map_err(|_| DomainError::AmountOutOfRange)?;
    Ok((Din(gross.0 - tax), Din(tax)))   // (سهم فروشنده، سهم خزانه)
}

۸.۲ دفتر دوطرفه — ledger.rs (پورت ADR-003)

pub fn post(state: &mut LedgerState, postings: Vec<Posting>,
            idem: Option<&str>) -> Result<Rc<PostedTx>, DomainError> {
    // بازپخش امن: کلید تکراری = برگشت تراکنش اصلی، بدون حرکت دوباره‌ی پول
    if let (Some(k), Some(tx)) = (idem, state.by_idem(k)?) { return Ok(tx); }

    if postings.len() < 2 { return Err(DomainError::TooFewPostings); }
    if postings.iter().map(|p| p.amount).sum::<i64>() != 0 {
        return Err(DomainError::UnbalancedTransaction);   // قاعده مقدس Σ=0
    }
    state.apply_direction_rules(&postings)?;   // overdraft/mint/burn → fail-closed
    state.commit(postings, idem)               // تغییرناپذیر: نسخه جدید state برگردانده می‌شود
}

۸.۳ ماشین حالت اسکرو — escrow.rs (پورت ADR-004)

pub enum EscrowStatus { Created, Funded, Delivered, Released,
                        Disputed, Refunded, Cancelled, Expired }

impl Escrow {
    /// هر مسیر غیرمجاز = رد تایپ‌دار. افزودن وضعیت جدید بدون به‌روزرسانی همه‌ی
    /// transitionها، پروژه را کامپایل نمی‌کند — خطا از تست به کامپایل می‌رود.
    pub fn transition(&mut self, ev: EscrowEvent) -> Result<Vec<DomainEvent>, DomainError> {
        match (&self.status, ev) {
            (EscrowStatus::Created,   ev) => self.fund(ev),          // خریدار → اسکرو
            (EscrowStatus::Funded,    EscrowEvent::Deliver) => self.deliver(),
            (EscrowStatus::Funded,    EscrowEvent::Dispute) => self.dispute(),
            (EscrowStatus::Delivered, EscrowEvent::Release) => self.release(),  // ۹۰/۱۰ + مالیات
            (EscrowStatus::Disputed,  ev) => self.arbitrate(ev),      // refund | release
            (EscrowStatus::Funded,    EscrowEvent::Cancel) => self.cancel(),
            (EscrowStatus::Funded,    EscrowEvent::Expire) => self.expire(),   // TTL sweep → بازگشت کامل
            _ => Err(DomainError::InvalidTransition),
        }
    }
}

🚨 برگشت (هر لحظه)
RUST_TRAFFIC_PCT=0 → ترافیک فوراً به TS برمی‌گردد؛ چون هر دو روی یک دیتابیس با invariantهای یکسان کار کرده‌اند، هیچ مهاجرت برگشتیِ داده لازم نیست. دامنه مجاز rollback: هر parity-fail، هر discrepancy مالی، p95 بدتر از ۲×baseline.
  • چرا برگشت ارزان است؟ قانون طلایی §6 — قرارداد ثابت. هر دو پیاده‌سازی همین قرارداد را اجرا می‌کنند؛ state مشترک است؛ پس سوییچ، routing decision است نه data migration.
  • سپر انسانی: در کل دوره dual-run، تراکنش‌های ≥ ۵۰,۰۰۰ Đ (مسیر HITL) فقط بعد از ۳ روز پایداری کامل به Rust می‌روند — آخرین لایه‌ای که سوییچ می‌شود، اولین چیزی که آدیت می‌شود.
  • مسیر abort کل پروژه: اگر تا پایان هفته ۱۲ گیت فاز ۴ سبز نشد، پروژه در همان گیت متوقف و به فاز ۷ مسیر TS برمی‌گردد؛ تمام کار تا آن لحظه (domain crate + persistence) به‌عنوان کتابخانه مالی قابل‌استفاده از TS (NAPI) ارزش خود را نگه می‌دارد — یعنی حتی «شکست» مسیر کامل، خروجی هیبرید می‌سازد.
